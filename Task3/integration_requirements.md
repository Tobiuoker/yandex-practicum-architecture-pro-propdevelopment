## Требования к внешним интеграциям

### Безопасность

- Передача данных только по защищенному каналу HTTPS/TLS.
- Доступ предоставляется по принципу минимальных привилегий.
- Секреты и ключи доступа хранятся в защищенном хранилище и регулярно ротируются.
- Все обращения к внешней платформе должны логироваться и контролироваться.

### Аутентификация и авторизация

- Для пользовательских интеграций используется OAuth 2.0 / OpenID Connect.
- Для межсервисного взаимодействия — OAuth 2.0 Client Credentials либо сервисные учетные записи.
- Права доступа ограничиваются ролями и необходимыми scope.

### Взаимодействие систем

Внутренние системы взаимодействуют с внешней платформой через API по HTTPS. Прямой доступ внешней платформы во внутреннюю сеть не предоставляется. Обмен выполняется через контролируемый интеграционный слой/API Gateway, где выполняются аутентификация, авторизация, логирование и ограничение запросов.
